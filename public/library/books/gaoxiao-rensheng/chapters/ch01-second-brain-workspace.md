# 第 1 章：第二大脑——从整理数位工作空间开始

## Core Idea
先把涌入的资讯接住、加工成可执行的下一步，再谈效率。本章三种方法分别解决“入口”（清空收件匣）、“存放”（PARA）与“产出”（卡片盒笔记法）：系统必须服务于行动与输出，而不是把资料排得漂亮。

## Frameworks Introduced

- **清空收件匣（Inbox Zero）**
  - When to use: 每天被邮件、即时通、临时交办淹没，任务在多个窗口间失焦。
  - How: 每天固定 1–3 个时段处理（刚上班、午休前、下班前），其余时间关闭通知。对每一项只做四种判断：删除、封存、2 分钟内回应、延后到正式工作流程。清空不等于全部完成，而是每一项都已分派。重要行程进日历，任务进待办清单，资讯进笔记，长文进稍后阅读。不要在邮件系统里管理工作。
  - Why it works: 固定时段降低任务切换成本；先判断“要不要做”而非“怎么做完”，避免收件匣变成黑洞。

- **PARA**
  - When to use: 笔记、档案、云端硬碟找不到，或分类越建越复杂。
  - How: 只设四个顶层分类——Projects（有截止日、可完成）、Areas（长期维持、无终点）、Resources（兴趣参考）、Archives（不再活跃）。从“正在执行的专案”开始建，不要一次搭完；资料在四类间动态移动。
  - Why it works: 以“可执行性”而非主题分类，能区分“现在要处理”与“以后才参考”，让资料自然流向行动。

- **卡片盒笔记法（Zettelkasten）**
  - When to use: 读了很多却写不出，或每次写作都从零开始。
  - How: 暂时笔记（Fleeting）先入收集箱 → 文献笔记（Literature）用自己的话重写并标来源 → 永久笔记（Permanent）一个想法一张、写清论述 → 在卡片盒（Slip-box）建立连结 → 写专案时建索引笔记（Project notes）重组。由下而上：先写许多卡片，主题会自己浮现。

## Key Concepts
- **收件匣**：因交派、询问而与“我”产生关联、但尚未排程的“可能任务”。
- **任务切换成本**：从一件事切到另一件，大脑需重新定向，消耗时间与专注。
- **中间产物封包**：可复用的分析、草稿、素材，像积木一样跨专案组合。
- **慢燃**：平时持续累积，让专案在真正开始时已处于“相对准备好”的状态。
- **文献笔记 / 永久笔记**：前者是带来源的转译，后者是可独立引用的完整观点。
- **卡片盒（Slip-box）**：只放永久笔记并建立脉络连结的知识网络。
- **专案笔记索引**：为某次写作从卡片盒抽出相关笔记的重组清单。

## Mental Models
- 把收件匣当“分派站”，不是“完成站”：判断优先于处理；能不做的事越多，重要流程越清楚。
- 用 PARA 分“可执行性”，不要按主题分：主题分类只会积累，专案分类才会推进。
- 写作不是“打开空白文件”，而是“把已有卡片重新编排”：先有素材，再有主题。
- 整理是执行的下游：先做专案，分类会自然长出来；先搭系统，往往没有动力执行。

## Anti-patterns
- **把收件匣归零理解为“全部处理完”**：会导致无限延后与焦虑；归零应是“全部已分派”。
- **一开始就搭完整 PARA 树**：花掉执行时间，且凭空设计的系统不符合真实需求。
- **只收集、画线、复制原文**：没有用自己的话转译，笔记无法复用。
- **把不同来源的笔记按时间堆在一起**：找得到位置，却找不回当时的思考。

## Worked Example
一份“学 Python”的资料如何移动：
1. 起初只是兴趣，放入 Resources / “程式码兴趣”。
2. 决定认真学，移入 Areas / “Python 技能学习”，持续投入。
3. 要架一个个人网站，切成 Projects / “三个月内架站”，资料全部挂到专案下。
4. 网站完成，移入 Archives；日后要查再搜寻。

关键不是四个格子，而是每次移动都对应一个真实行动：兴趣→长期领域→有期限专案→封存。若一开始就把四层分类和子标签全部建好，反而会在“整理”上耗尽执行专案的动力。

## Key Takeaways
1. 清空收件匣的关键是“分派”，不是“做完”；固定时段处理，保护专注。
2. PARA 从专案开始建，按可执行性分类，让资料跟着行动走。
3. 卡片盒的价值在“用自己的话写下永久笔记并连结”，而不是收集。
4. 中间产物封包与慢燃，让下一次专案不必从零开始。
5. 系统越简单、越贴近执行，越可能被持续使用。
